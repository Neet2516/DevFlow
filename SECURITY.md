# Security Policy

## Supported Versions

DevFlow active security updates apply to the latest main branch releases.

| Version | Supported          |
| ------- | ------------------ |
| 1.x.x   | :white_check_mark: |
| < 1.0   | :x:                |

## Reporting a Vulnerability

The DevFlow team takes security vulnerabilities seriously. We appreciate your efforts to responsibly disclose findings.

### How to Report
- **Please DO NOT report security vulnerabilities through public GitHub issues.**
- Submit private security reports directly to the maintainers or via GitHub Security Advisories.
- Email vulnerability details to: `security@devflow.org` (or open a private vulnerability report via GitHub Security tab).

### What to Include in Your Report
1. Description of the vulnerability and potential impact.
2. Steps to reproduce the issue (including proof of concept scripts or API payloads if applicable).
3. Any suggested remediations or patches.

### Disclosure & Response Process
- **Acknowledgement**: We aim to acknowledge receipt of your security report within 48 hours.
- **Triage & Patching**: We will investigate and provide regular updates until a patch is developed and verified.
- **Public Disclosure**: Once fixed, a security advisory will be published with credit attributed to the reporter (unless requested otherwise).
